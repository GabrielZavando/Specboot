## Why

The first `release.yml` run after merging `cleanup-publish-and-junk` failed in the
`npm publish` step with `You cannot publish over the previously published versions: 0.1.1`:

1. **Root cause (blocking)**: the PR was merged to `main` without bumping `package.json`.
   `release.yml` intentionally does NOT auto-bump (per `specboot-release` spec: the
   maintainer bumps SemVer before merge). The maintainer's `update.sh --bump` only
   writes CHANGELOG + git tag — it never edits `package.json` — so the version stayed
   at the already-published `0.1.1`.

2. **Secondary (cosmetic but misleading)**: npm emitted
   `"bin[specboot]" script name specboot.sh was invalid and removed`. Per the
   `@npmcli/package-json` normalization source, that message only means the path was
   normalized (`./specboot.sh` → `specboot.sh`); the `bin` field SURVIVES in the
   published package. It can be silenced by declaring the bin path pre-normalized.

## What Changes

- **Updates** `package.json`:
  - `version`: `0.1.1` → `0.1.2` (patch — release/publish fix).
  - `bin.specboot`: `./specboot.sh` → `specboot.sh` (pre-normalized; silences the
    publish warning; the shipped CLI entry is unaffected).
- **Updates** `CHANGELOG.md`: adds the `0.1.2` entry (Keep a Changelog format).
- **Updates** `openspec/specs/npm-distribution/spec.md`: Requirement "Package
  configuration" no longer hardcodes the `./` prefix in the bin entry, and the
  documented version moves to `0.1.2`.

## Goals

- Unblock the automated publish: the next push to `main` publishes `0.1.2` via `release.yml`.
- Make `package.json` bin normalization-clean so future publishes emit no bin warnings.

## Non-Goals

- **No** workflow changes: `release.yml` keeps NOT doing automatic version bump —
  the maintainer bumps before merge (this change IS that bump).
- **No** changes to `update.sh` (its `--bump` remains CHANGELOG+tag only, by design).
- **No** fix for the `npm warn Unknown user config "always-auth"` line: it comes from
  the runner-side `.npmrc` generated by `actions/setup-node`, not from this repo
  (there is no repo-level `.npmrc`), and it is non-blocking.
