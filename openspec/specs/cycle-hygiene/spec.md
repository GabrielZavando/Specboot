## Requirements
### Requirement: The build agent owns the Mandatory Steps tick

The build agent (`ai-specs/agents/build-agent.md`) SHALL tick each Mandatory Steps checkbox in `tasks.md` via the edit tool at the moment the step is satisfied (pre-implementation branch/git checks, RED before implementation, module tests during iteration, verify and adversarial-review post-implementation), so `/apply` finishes with zero open Mandatory Steps checkboxes.

#### Scenario: apply ticks steps as they are satisfied
- **GIVEN** a change with a `## Mandatory Steps` section in its `tasks.md` being executed via `/apply`
- **WHEN** the build agent satisfies each step
- **THEN** the corresponding checkbox is marked `[x]` via the edit tool at that moment, and `/apply` ends with no open Mandatory Steps checkboxes

### Requirement: archive is defensive, not the canonical tick owner

The `archive` skill SHALL treat `/apply` as the canonical owner of the Mandatory Steps tick. Archive only defensively ticks satisfied leftovers via the edit tool (never `sed -i`) and aborts on genuinely pending implementation tasks. The standard cycle SHALL NOT require the `--yes` flag because of Mandatory Steps checkboxes.

#### Scenario: archive proceeds without --yes in the standard cycle
- **GIVEN** a change whose `/apply` ticked its Mandatory Steps
- **WHEN** `/archive` parses `tasks.md`
- **THEN** no Mandatory Steps `- [ ]` remain and archive proceeds without `--yes`; a satisfied leftover is defensively ticked via the edit tool; a genuinely pending task aborts the archive

### Requirement: The roadmap reflects the executed cycle

`PLAN_MEJORAS_SPECBOOT.md` SHALL mark M-701 as `## [x]`, register M-908 as a completed ticket (`## [x] M-908`) following the M-403 pattern (SemVer level and dependencies declared), and add a history row covering the M-701 + M-908 + M-909 cycle.

#### Scenario: roadmap registers the completed cycle
- **GIVEN** `PLAN_MEJORAS_SPECBOOT.md` with M-701 unmarked and M-908 unregistered
- **WHEN** the change is applied
- **THEN** M-701 is marked `## [x]`, M-908 appears as `## [x] M-908`, and the history row for the cycle exists

### Requirement: The proposal template carries Why and What Changes

The `plan-change` skill proposal template SHALL include `## Why` and
`## What Changes` sections, and its Step 6 checklist SHALL validate their
presence AND the length of `## Why` (maximum 1000 characters) before reporting
success, so proposals generated by the template do not trigger the
`openspec archive` proposal warning and never exceed the length limit.

#### Scenario: template-generated proposal passes without warnings

- **GIVEN** the updated `plan-change` template
- **WHEN** a new change proposal is generated
- **THEN** it includes `## Why` and `## What Changes`, the `## Why` length is
  validated (≤ 1000 characters) before success is reported, and
  `openspec archive` emits no proposal warning for it

#### Scenario: an overlong Why is caught before success

- **GIVEN** a proposal whose `## Why` exceeds 1000 characters
- **WHEN** the Step 6 validation runs
- **THEN** the length violation is reported and success is not declared

### Requirement: The /apply pre-flight is resumable and runs once per change

The `/apply` pre-flight (branch convention + git state) MUST run once per
change, not before every task. On the first execution, dirt MUST be allowed
when limited to `openspec/changes/{active-change}/**` (the artifacts created by
`/plan-change`); changes unrelated to the active change MUST keep blocking the
entry. Once implementation has started, `/apply` MUST accept the changes
produced by previous tasks of the change and MUST resume from the first pending
task (`- [ ]` in `tasks.md`); it MUST NEVER require intermediate commits. The
`commit` agent keeps exclusive ownership of `git add`, `git commit` and
`git push`. The pre-flight marker (whatever mechanism implements the once-per-
change semantics) MUST NOT interfere with the verify/adversarial evidence files
(`openspec/state/*-results.json` remain fail-closed for `build`), and the
interplay with the `## Mandatory Steps` checklist ("Estado git limpio"
interpreted at change level per this requirement) MUST be explicit in
`apply.md`.

#### Scenario: /apply starts with planning artifacts without a manual commit

- **GIVEN** a change freshly generated by `/plan-change` with dirt limited to
  `openspec/changes/{active-change}/**` and a correct ticket branch
- **WHEN** `/apply` runs its pre-flight for the first time
- **THEN** it passes without requiring a commit or stash, and the first task's
  implementation starts normally

#### Scenario: /apply resumes over the expected dirty tree

- **GIVEN** a change in execution with at least one completed task (uncommitted
  code changes produced by previous tasks)
- **WHEN** `/apply` resumes the change
- **THEN** the pre-flight does not block on the change's own dirty tree
- **AND** `/apply` continues from the first pending task without intermediate
  commits

#### Scenario: Foreign pre-existing changes still block /apply

- **GIVEN** uncommitted changes unrelated to the active change before
  implementation starts
- **WHEN** `/apply` runs its pre-flight
- **THEN** the entry is blocked with an explicit message listing the foreign
  files and asking for commit or stash

### Requirement: Archive documentation matches its actual behavior

The `/archive` command description and the `archive` skill documentation MUST
match the effective configuration: the command description MUST NOT promise
staging (staging and commit are the exclusive ownership of the `commit` agent)
and all archive paths MUST use the canonical `openspec/changes/archive/`
location.

#### Scenario: archive command no longer promises staging

- **GIVEN** the corrected `.opencode/commands/archive.md`
- **WHEN** its front matter description is inspected
- **THEN** it does not promise staging for `/commit`

#### Scenario: archive uses the canonical path

- **GIVEN** the corrected `ai-specs/skills/archive/SKILL.md`
- **WHEN** the archive paths are inspected
- **THEN** the canonical `openspec/changes/archive/` location is used
  consistently
