## Requirements
### Requirement: enrich-us output MUST include strategic evaluation metadata
The `enrich-us` skill SHALL output four strategic evaluation sections: Estimación (complexity and justification), Riesgo (risk level and reason), Dependencias (related tickets), and Alternativas descartadas (discarded alternatives).

#### Scenario: Enriched story includes strategic metadata
- **GIVEN** a story enriched via the `enrich-us` skill
- **WHEN** the output file is generated
- **THEN** it includes sections for Estimación, Riesgo, Dependencias, and Alternativas descartadas

### Requirement: Acceptance scenarios MUST include SC-NNN stable identifiers
All Gherkin acceptance scenarios generated by `enrich-us` and `plan-change` SHALL carry a unique `SC-{NNN}` prefix in their title header (e.g. `### SC-001: Scenario title`).

#### Scenario: Scenarios contain SC-NNN identifier
- **GIVEN** an OpenSpec change or enriched ticket artifact
- **WHEN** acceptance scenarios are rendered
- **THEN** every scenario header starts with `### SC-` followed by a three-digit integer and title

### Requirement: verify skill MUST track test coverage by SC-NNN pattern
The `verify` skill SHALL match test evidence against Gherkin scenarios using the `SC-{NNN}` pattern and map each scenario to PASS, FAIL, or UNTESTED status.

#### Scenario: Verify skill maps test evidence using SC-NNN
- **GIVEN** an active change with `scenarios.md` containing `SC-{NNN}` identifiers
- **WHEN** `verify` runs test verification
- **THEN** it matches test cases by `SC-{NNN}` pattern and includes the mapping in its summary
